# Запуск чат-бота СДУТ в MAX

Это инструкция именно для бота MAX. Репозиторий `telegram-emulator` используется как хранилище файлов и среда тестирования; Telegram emulator не является транспортом этого бота.

## 1. Тест на ноутбуке — Long Polling

1. Скачайте ZIP ветки `max-bot-complete-2026`.
2. Распакуйте папку.
3. Установите Python 3.10+ (рекомендуется 3.13).
4. Откройте PowerShell в папке.
5. Выполните:

```powershell
python launcher.py
```

Launcher создаст `.venv`, установит зависимости, запросит токен MAX при первом запуске и запустит `run_max.py`.

### Токен

В MAX откройте `@MasterBot`, выполните `/create` и получите токен. Если launcher спросит его — вставьте одной строкой. Токен сохранится в `token.txt`, который не коммитится в Git.

### Что запускается

`launcher.py` → `run_max.py` → `max_bot.py`.

`run_max.py` подключает SQLite-хранилище `data/sdut_bot.sqlite3`, восстановление состояния анкеты и persistent-защиту от повторной доставки событий.

`max_bot.py` не переписывается и остаётся эталонным сценарием/диспетчером.

### Ограничение Long Polling

Long Polling предназначен для разработки и тестирования на ноутбуке. Публичный IP, домен, HTTPS и открытый порт для него не нужны. Окно с ботом должно оставаться открытым.

## 2. Production — Webhook + PostgreSQL

Для серверной эксплуатации используйте `run_max_webhook.py`. При заданном `SDUT_DATABASE_URL` он автоматически выбирает PostgreSQL. SQLite остаётся только для локального пилота.

Рекомендуемая схема:

```text
MAX
  │ HTTPS :443
  ▼
reverse proxy (Nginx/Caddy, доверенный сертификат)
  │ HTTP localhost
  ▼
127.0.0.1:8080/max
  │
  ▼
run_max_webhook.py → max_webhook.py
  │
  ▼
PostgreSQL
```

MAX должен видеть именно публичный адрес вида:

```text
https://bot.example.ru/max
```

Не используйте в `MAX_WEBHOOK_URL` `http://`, `:8080` или `:8443`. Внутренний порт приложения задаётся отдельно через `MAX_WEBHOOK_PORT`.

### Переменные окружения

```text
MAX_BOT_TOKEN=...
SDUT_DATABASE_URL=postgresql://sdut_user:STRONG_PASSWORD@127.0.0.1:5432/sdut
MAX_WEBHOOK_URL=https://bot.example.ru/max
MAX_WEBHOOK_PATH=/max
MAX_WEBHOOK_HOST=127.0.0.1
MAX_WEBHOOK_PORT=8080
MAX_WEBHOOK_SECRET=...
```

Секреты не храните в Git, Docker image, shell history или открытом `.env`. Для production используйте секрет-хранилище или защищённый environment file с правами только для пользователя процесса.

Если `MAX_WEBHOOK_SECRET` не задан, приложение создаёт стабильный секрет в `.webhook_secret`. Для production лучше задать секрет явно через защищённую переменную окружения.

### Важное про переключение

Не запускайте Long Polling и Webhook одновременно для одного бота.

`max_webhook.py` регистрирует новую Webhook-подписку через `POST /subscriptions` и не удаляет старую подписку заранее: это предотвращает лишнее окно потери доставки при ошибке новой настройки.

Webhook должен быстро вернуть успешный HTTP-ответ. В текущей архитектуре тяжёлую бизнес-логику пока не вынесли в отдельную очередь: перед высокой нагрузкой это следующий обязательный production-hardening этап.

## 3. Проверки перед запуском

На ноутбуке:

```powershell
python -m compileall max_bot.py storage_sqlite.py max_webhook.py
python -m pytest tests/test_storage_sqlite.py tests/test_webhook_config.py
python launcher.py
```

Для PostgreSQL/production:

```powershell
python -m compileall max_bot.py storage_postgres.py max_webhook.py run_max_webhook.py
python -m pytest tests/test_storage_sqlite.py tests/test_storage_postgres.py tests/test_webhook_config.py
$env:SDUT_DATABASE_URL="postgresql://sdut_user:STRONG_PASSWORD@127.0.0.1:5432/sdut"
python run_max_webhook.py
```

Диагностика подключения:

```powershell
python diagnose.py
```

## 4. Данные и границы ответственности

SQLite находится в `data/sdut_bot.sqlite3` и исключён из Git. Не передавайте базу третьим лицам: она может содержать персональные данные обращавшихся.

PostgreSQL — рекомендуемое production-хранилище. Нужны отдельные процедуры резервного копирования, восстановления, ротации/удаления персональных данных и контроля доступа.

Даже с PostgreSQL этот бот не становится МИС и не выполняет медицинскую диагностику. Он остаётся навигационным слоем: анкета → типизация → маршрут → передача обращения координатору.
