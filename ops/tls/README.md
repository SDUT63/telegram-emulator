# TLS: как открыть бота для MAX

MAX доставляет события только по HTTPS и только на порт 443. Без этого
бот в боевом режиме не работает вовсе — он и не поднимется: при старте
он проверяет, что `MAX_WEBHOOK_URL` начинается с `https://` и ведёт
на 443.

Сам бот шифрованием не занимается и слушает `127.0.0.1:8080`. TLS
заканчивается на nginx, а до бота остаётся петля внутри машины.
Так проще обновлять сертификат и так меньше мест, где можно ошибиться.

## 1. Что нужно заранее

* доменное имя, у которого A-запись указывает на этот сервер;
* открытые снаружи порты 80 и 443;
* nginx (`apt install nginx`).

Порт 80 нужен не для работы, а для выпуска и продления сертификата.
Всё, что на него приходит, кроме проверки Let's Encrypt, уходит на HTTPS.

## 2. Конфигурация nginx

```bash
sudo cp ops/tls/nginx-sdut.conf /etc/nginx/sites-available/sdut
sudo sed -i 's/ПОСТАВЬТЕ_СВОЙ_ДОМЕН/бот.вашдомен.ру/g' /etc/nginx/sites-available/sdut
sudo ln -s /etc/nginx/sites-available/sdut /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
```

Если у сервера есть IPv6, раскомментируйте в конфиге строки `listen [::]`.
Если нет — оставьте закомментированными: с ними nginx не поднимется.

## 3. Сертификат

```bash
sudo apt install certbot python3-certbot-nginx
sudo certbot certonly --webroot -w /var/www/html -d бот.вашдомен.ру \
     --agree-tos -m почта@службы.ру
sudo nginx -t && sudo systemctl reload nginx
```

Продление certbot берёт на себя: он ставит свой таймер и обновляет
сертификат за месяц до истечения. Проверить, что таймер есть:

```bash
systemctl list-timers 'certbot*'
sudo certbot renew --dry-run
```

## 4. Настройки бота

В `/etc/sdut/bot.env`:

```
MAX_WEBHOOK_URL=https://бот.вашдомен.ру/max
MAX_WEBHOOK_PATH=/max
MAX_WEBHOOK_HOST=127.0.0.1
MAX_WEBHOOK_PORT=8080
```

Путь в трёх местах должен совпадать: в `MAX_WEBHOOK_URL`, в
`MAX_WEBHOOK_PATH` и в `location = /max` конфига nginx. Бот проверяет
первые два при старте и не поднимется, если они разошлись; третье
не проверит никто, кроме вас.

## 5. Проверить, что получилось

```bash
python preflight.py                 # строка «Доступ снаружи (TLS)»

# Вебхук отвечает:
curl -i -X POST https://бот.вашдомен.ру/max -d '{}'

# Счётчики и состояние наружу закрыты — обе строки должны дать 404:
curl -o /dev/null -w '%{http_code}\n' https://бот.вашдомен.ру/metrics
curl -o /dev/null -w '%{http_code}\n' https://бот.вашдомен.ру/health

# Сертификат и срок:
echo | openssl s_client -connect бот.вашдомен.ру:443 2>/dev/null \
     | openssl x509 -noout -subject -dates
```

## Что решено в конфигурации и почему

**Наружу открыт один путь.** `/metrics` отдаёт счётчики работы,
`/health` — состояние базы. В интернете они не нужны никому. Всё, кроме
вебхука, отвечает 404, а не 403: знать, что здесь что-то есть,
посторонним незачем.

**Ограничение частоты: 10 запросов в секунду с адреса, всплеск 20.**
Бот публичный — ссылку видят все, кому показали рекламу. Человеку
хватает одного запроса в несколько секунд; всплеск нужен, потому что
MAX иногда досылает накопленное пачкой. Проверено: из шестидесяти
запросов подряд двадцать восемь проходят, тридцать два получают 429,
а через секунду приём возобновляется.

**Тело не больше мегабайта.** Событие MAX — небольшой JSON. Мегабайта
хватает с запасом, а залить в бота файл уже нельзя. Проверено: два
мегабайта отвергаются с кодом 413.

**Только TLS 1.2 и 1.3.** Всё, что старше, сломано, и MAX этого
не требует.

**HTTP/2 не включён.** Он выигрывает там, где браузер тянет десятки
файлов разом; вебхук — это одиночные POST. Зато синтаксис включения
менялся между версиями nginx, и конфиг под одну не поднимается на
другой: на nginx 1.24 из Ubuntu LTS `http2 on` — ошибка, а не
предупреждение. Проверено.

**В журнал не попадает тело запроса.** В нём переписка людей.
Записываются адрес, время, метод, путь, код ответа и время обработки.

**CRM наружу не открыта.** В ней имена, телефоны, адреса и сведения
о здоровье. Заготовка в конце конфига закомментирована и требует явно
указать, кому можно: сеть службы или VPN. Пароль оператора — не тот
рубеж, за которым такие сведения можно оставить в открытой сети.
