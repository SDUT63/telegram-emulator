# Чат-бот «Точка входа» для мессенджера MAX

Бот принимает обращение от человека, которому нужна помощь по уходу, или от того,
кто обращается в его интересах: собирает контактные сведения, проходит обязательный
фильтр экстренных состояний и передаёт карточку обращения координатору АНО «СДУТ».

Бот — это канал первичного обращения, а не служба помощи. Он не ставит диагнозов,
не определяет уровень нуждаемости, не обещает срок и объём чужой услуги и не называет
заявителю организацию-получателя: это делает координатор при звонке.

## Что бот собирает

Состав полей взят из перечня обязательных полей и чек-листа первичного обращения
методических рекомендаций АНО «СДУТ» (глава 13.1, приложение 4):

| Поле | Зачем |
| --- | --- |
| Дата и время обращения, канал | Расчёт срока, аналитика каналов |
| ФИО заявителя и телефон | Обратная связь и контрольный звонок |
| Кем приходится подопечному | Правомочность и адресат контроля |
| ФИО и возраст подопечного | Идентификация в профильной организации |
| Знает ли подопечный об обращении | Корректность контрольного звонка |
| Район и адрес | Выбор получателя по территории |
| Суть обращения со слов заявителя | Содержание маршрутного листа |
| Ограничения самообслуживания: передвижение, гигиена, питание | Разграничение М1 / М2 / М3 |
| Наличие и загруженность ухаживающего | Разграничение М2 и М3 |
| Боль или медицинский контроль на дому со слов заявителя | Признак М1 |
| Текущие социальные услуги, прошлые обращения | Данные по М2, история случая |
| Другие сферы: документы, транспорт, ТСР, опека, финансы | Признак М5 |
| Кто будет на связи и удобное время звонка | Контроль на 7-й день |
| Отметка STOP-1 / STOP-2 | Допуск в навигационный контур |
| Согласие на обработку персональных данных | Условие приёма обращения |

**Не собираются и не хранятся:** диагноз, назначения, медицинские документы, СНИЛС,
полис, паспортные данные, сведения о доходах, имуществе и составе семьи. Ни одно поле
такого рода не влияет на выбор маршрута, поэтому вопросов о них в анкете нет.

Согласие на передачу сведений конкретному получателю бот **не** собирает: одно согласие —
один получатель, а получатель известен только после решения о маршруте. Это согласие
оформляет координатор.

## Фильтр STOP-1

Перед анкетой бот дословно задаёт вопросы из закрытого перечня признаков экстренного
состояния. При ответе «да» хотя бы на один вопрос:

1. анкета останавливается, бот называет номера 103 и 112;
2. фиксируются признак и время его выявления;
3. карточка немедленно уходит координатору с пометкой «STOP-1»;
4. у заявителя запрашиваются только имя и телефон — чтобы координатор перезвонил
   на следующий рабочий день.

Если ни один признак не выявлен, в карточке ставится отметка STOP-2 — формальный
допуск случая в навигацию.

**Перечень признаков утверждает и подписывает заведующий отделением паллиативной
медицинской помощи.** Пока в конфигурации `stop1.approved: false`, бот не принимает
обращения и отвечает, что приём не открыт, называя телефон службы и номера экстренных
служб. Список в `configs/maxbot.yaml` — черновик для наладки; замените его утверждённым.

## Предварительный маршрут

По ответам бот рассчитывает подсказку маршрута по матрице М1–М5 (приложение 3) и
кладёт её в карточку координатора вместе с обоснованием. Заявителю маршрут не называется.
Порядок правил:

1. заявитель не смог ответить на часть вопросов → **М4** (спорный случай);
2. отмечены дополнительные сферы вместе с потребностью в уходе или медицине → **М5**;
3. со слов заявителя есть боль, которая не снимается, или нужен медицинский контроль на дому → **М1**;
4. утрата самообслуживания по трём позициям → **М3**;
5. частичная утрата и ухаживающий есть → **М2**;
6. утрата без ухаживающего → **М4**.

Маршрут — подсказка, а не решение: уровень нуждаемости устанавливает эксперт,
маршрут при сомнении определяет координатор.

## Карточка координатора

После отправки анкеты карточка уходит в чат координаторов (`coordinator.chat_id`)
и/или в личные сообщения (`coordinator.user_ids`). В карточке: номер обращения, канал,
дата и время, отметка фильтра, согласие, контакты, район и адрес, суть со слов заявителя,
ограничения, предварительный маршрут с обоснованием и обязательное поле
**«владелец следующего действия»** с датой.

## Запуск

1. Создайте бота в MAX через MasterBot и получите токен.
2. Скопируйте `configs/maxbot.yaml` и заполните: организация, телефон, районы,
   получатели карточек, утверждённый перечень STOP-1.
3. Узнайте идентификаторы координаторов: они пишут боту команду `/id`.
4. Запустите:

```bash
export MAXBOT_BOT_TOKEN="токен от MasterBot"
make maxbot-run          # или: go run ./cmd/maxbot
```

Сборка бинарного файла: `make maxbot-build` → `build/maxbot`.

### Режимы получения обновлений

* `bot.mode: polling` — long polling, ничего публиковать наружу не нужно. Подходит для
  запуска на любой машине и для наладки.
* `bot.mode: webhook` — бот подписывается на webhook и слушает `bot.webhook.listen`
  по пути `bot.webhook.path`. Нужен публичный HTTPS-адрес в `bot.webhook.url` и
  секрет `bot.webhook.secret` (MAX присылает его в заголовке `X-Max-Bot-Api-Secret`).

### Переменные окружения

Любой параметр конфигурации переопределяется переменной с префиксом `MAXBOT_`:
`MAXBOT_BOT_TOKEN`, `MAXBOT_BOT_MODE`, `MAXBOT_DATABASE_URL`, `MAXBOT_COORDINATOR_CHAT_ID`.
Токен в репозитории не хранится.

## Команды бота

Для заявителя: `/start`, `/apply`, `/my`, `/cancel`, `/help`, `/id`.
Для координаторов (перечислены в `coordinator.user_ids`): `/last` — последние обращения,
`/card НОМЕР` — карточка целиком.

## Данные

Обращения хранятся в SQLite (`database.url`, по умолчанию `data/maxbot.db`) в двух
таблицах: `maxbot_applications` — карточки, `maxbot_events` — журнал событий по случаю
(начало анкеты, STOP-1, отказ от согласия, отправка). Журнал обеспечивает
восстановимость истории случая.

Файл базы содержит персональные данные: храните его на защищённой машине,
ограничьте доступ и настройте резервное копирование по правилам организации.

## Тесты

```bash
make maxbot-test    # или: go test ./internal/maxbot/...
```

Тесты покрывают: прохождение анкеты целиком, протокол STOP-1, отказ от согласия,
пропуск неприменимых вопросов, проверку ответов, матрицу маршрутов М1–М5,
нумерацию обращений и журнал событий.

## Структура кода

```
cmd/maxbot/main.go            запуск, polling или webhook
internal/maxbot/config        конфигурация и её проверка
internal/maxbot/models        карточка обращения и журнал
internal/maxbot/storage       хранилище на SQLite
internal/maxbot/survey        анкета: шаги, проверка ответов, матрица маршрутов, карточка
internal/maxbot/bot           связь анкеты с MAX Bot API: команды, кнопки, контакты
```

Логика анкеты отделена от API: пакет `survey` не знает про MAX и покрыт тестами
без обращения к сети, а пакет `bot` общается с MAX через интерфейс `Outbox`.
