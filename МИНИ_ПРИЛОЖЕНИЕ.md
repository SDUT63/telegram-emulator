# Мини-приложение кнопкой внутри MAX

Как сделать, чтобы страница службы открывалась в MAX по кнопке рядом
с ботом.

## Что открывается по адресу

По корню адреса лежит **мини-приложение**. Шесть вкладок, и открывается
оно на первой:

1. **План ухода** — девять вопросов об устройстве дня и дома, и сразу
   распорядок с действиями, частотой и минимумом оборудования. С анкетой
   бота не пересекается: там спрашивают, какой человек, здесь — как
   устроен его день.
2. **Справочник** — поиск по всем материалам службы, с картинками.
3. **Сколько часов положено** — расчёт по оценочной шкале Приказа № 731.
4. **Сколько стоит** — калькулятор платного ухода с надбавками и тем,
   какую часть часа закрывают программы.
5. **Оборудование** — что положено даром и почём аренда.
6. **Анкета** — те же вопросы, что задаёт бот, плюс список документов.

Раньше по корню лежал «Навигатор помощи» целиком — длинная страница,
по которой надо было листать до нужного места. Её больше нет: все её
статьи перенесены в базу знаний и ищутся поиском вместе с остальными,
вместе с картинками. Согласие на обработку данных, реквизиты и
источники тоже там — наберите «согласие» или «реквизиты».

| Файл в папке `webapp` | Что это |
|---|---|
| `index.html` | мини-приложение — то, что открывает кнопка в MAX |
| `app.html` | переадресация на корень для старых ссылок |
| `img/` | картинки справочника |

Файлы `scale.json`, `kb.json`, `survey.json`, `price.json` — это те же
данные отдельно, для проверки. Приложению они не нужны: всё вшито
внутрь `index.html`.

## Что требуется

Мини-приложение MAX открывается **только по адресу на HTTPS**. Файл с
компьютера туда вставить нельзя — у страницы должен быть адрес в интернете.

Сейчас приложение живёт по постоянному адресу:

**https://sdut.d-lemeshev88.workers.dev/**

Он опубликован на Cloudflare — этот адрес и стоит в настройках бота.
Ниже — как выложить туда новую версию, и что делать, если понадобится
проверить черновик, не трогая рабочий адрес.

| Путь | Ссылка | Когда |
|---|---|---|
| **Обновить рабочий адрес** | та же, менять в MAX ничего не надо | обычный случай: правки в справочнике |
| **Туннель Cloudflare** | временная, живёт пока открыто окно | проверить черновик, не трогая рабочий |

## Когда обновлять Cloudflare нужно, а когда нет

Это два разных хозяйства, и путать их дорого.

**На Cloudflare лежит только папка `webapp`** — справочник, который
открывается кнопкой в MAX. Это статические страницы: HTML, картинки,
никакого Python и никакой базы. Cloudflare ничего не исполняет и
ничего не знает ни об анкете, ни об обращениях.

**Бот живёт отдельно** — на вашем сервере или ноутбуке. Анкета,
распознавание угрозы жизни, карточки координатора, CRM, база данных,
резервные копии — всё это там, и к Cloudflare отношения не имеет.

| Что изменилось | Надо ли трогать Cloudflare |
|---|---|
| Правки в `webapp/`: текст справочника, картинки, схемы | **Да** — выложить папку заново |
| Вопросы анкеты, распознавание угрозы жизни, ответы бота | Нет |
| CRM, операторы, роли, пароли | Нет |
| База данных, миграции, резервные копии | Нет |
| TLS, systemd, запуск бота на сервере | Нет |

Проверить, менялся ли справочник, можно одной командой в папке
с ботом:

```powershell
git log --oneline -5 -- webapp/
```

Если последняя запись старая — на Cloudflare выкладывать нечего.

> **Отдельно про счётчик.** У локального `webapp_server.py` есть адрес
> `/stats` с числом обращений. На Cloudflare он не работает и работать
> не может: там некому считать. Это нормально — счётчик нужен не
> посетителю справочника, а вам, и смотреть его надо через
> `python funnel.py` на сервере.

## Путь 1. Обновить то, что уже опубликовано

Адрес `sdut.d-lemeshev88.workers.dev` — это Cloudflare. Обновляется он
там же, где был создан: **dash.cloudflare.com** → раздел
**Workers & Pages** → проект `sdut`.

Дальше зависит от того, как проект был создан, и это видно на его
странице:

* **страница проекта предлагает загрузить файлы** («Upload assets»,
  «Загрузить ресурсы», «Create new deployment») — перетащите туда
  **папку `webapp` целиком**, вместе с `index.html`, `app.html`
  и папкой `img` — картинки к статьям лежат в ней.
  Через минуту новая версия открывается по тому же адресу;
* **страница проекта показывает редактор кода** («Edit code», «Quick
  edit») — значит, страница вшита в сам скрипт воркера. Тогда откройте
  редактор, замените содержимое на новое и нажмите **Deploy**;
* **проект связан с репозиторием GitHub** — тогда достаточно отправить
  изменения в ветку, и Cloudflare пересоберёт сам.

Адрес при любом из вариантов остаётся прежним, и в настройках MAX
менять ничего не нужно.

> **Что именно выкладывать.** Папку `webapp`: `index.html`, `app.html`,
> папку `img` и, если нужны, `Инструкция-чат-бот-СДУТ.html`
> и папку `инструкция`. Папка `img` обязательна: без неё статьи
> откроются без картинок.
> Не выкладывайте `token.txt`, `survey_responses.json`, `crm_data.json`,
> `operators.json` и папку `outbox` — там ключ доступа и данные людей.
> В папке `webapp` их и нет, но проверьте, что перетаскиваете именно её,
> а не всю папку с ботом.

## Путь 2. Туннель (проверить черновик, не трогая рабочий адрес)

### Окно 1 — сервер страницы

Откройте папку `sdut-bot`, наберите `powershell` в адресной строке:

```powershell
python webapp_server.py
```

Должно появиться `Страница открыта: http://localhost:5000`. Окно не
закрывайте.

### Окно 2 — туннель

Если `cloudflared` ещё не установлен:

```powershell
winget install --id Cloudflare.cloudflared
```

Затем **в новом окне PowerShell**:

```powershell
cloudflared tunnel --url http://localhost:5000
```

Через несколько секунд среди строк появится адрес вида

```
https://states-with-projected-excluded.trycloudflare.com
```

Скопируйте его.

### В настройках бота MAX

1. Раздел **Мини-приложение** → поле **Введите ссылку**.
2. Вставьте адрес из окна 2.
3. Ниже выберите кнопку **Открыть**.
4. Нажмите **Сохранить**.

Готово: у бота появится кнопка, открывающая справочник внутри MAX.

### Оговорка

**Адрес живёт, пока запущен туннель.** Закрыли окно или перезагрузили
компьютер — адрес пропал, при следующем запуске выдадут новый, и его придётся
заново вставлять в настройки MAX.

Для проверки это нормально. Для людей — нет: у них кнопка перестанет работать.

## Если адрес придётся заводить заново

1. Зарегистрируйтесь на **dash.cloudflare.com** (бесплатный тариф).
2. **Workers & Pages** → создать проект → загрузка готовых файлов
   (**Upload assets** или «Загрузить ресурсы» — формулировки меняются).
3. Перетащите папку `webapp` целиком.
4. Cloudflare выдаст постоянный адрес.
5. Вставьте его в настройки мини-приложения MAX и **впишите сюда, в этот
   файл**, — чтобы в следующий раз не искать.

## Почему по сети отдаётся не единый файл

Сервер отдаёт `index.html` вместе с папкой `img`, а не
`Навигатор-помощи-СДУТ.html`.

Единый файл весит 4,5 МБ, потому что картинки вшиты внутрь — его пришлось бы
скачивать целиком при каждом открытии, в том числе с телефона по мобильному
интернету. Обычная версия — 135 КБ: открывается сразу, картинки подгружаются
по мере прокрутки и запоминаются браузером на сутки.

Единый файл нужен для другого — скачать и открыть без интернета.

## Если что-то не так

| Что видите | Что делать |
|---|---|
| В MAX кнопка есть, но страница пустая | Проверьте, что оба окна открыты, а адрес в настройках совпадает с текущим адресом туннеля |
| `cloudflared не распознано` | Не установлен. `winget install --id Cloudflare.cloudflared`, затем закройте и откройте PowerShell заново |
| Страница открывается, но без картинок | Отдаётся не та версия либо потерялась папка `img`. Проверьте `http://localhost:5000` в браузере |
| Адрес туннеля перестал работать | Так и задумано — он временный. Запустите туннель заново и вставьте новый адрес, либо переходите к Pages |
| `Address already in use` | Порт занят прошлым запуском. Закройте старое окно или запустите `$env:PORT=5001; python webapp_server.py` |

## Бот и страница — разные вещи

Они друг от друга не зависят:

- **бот** (`max_bot.py`) подключается к MAX сам, ему сервер и адрес не нужны;
- **страница** (`webapp_server.py` + туннель или Pages) нужна только для
  кнопки мини-приложения.

Можно запускать по отдельности.

## Перенос ответов из бота в приложение

Анкета одна и та же в боте и в приложении. Чтобы человек не отвечал
дважды, бот отдаёт ссылку, внутри которой ответы уже лежат: достаточно
написать боту «приложение», «калькулятор» или «сколько стоит».

Ответы едут в части адреса после решётки. Эту часть браузер на сервер
не отправляет — в журналах Cloudflare их не окажется. Приложение читает
их, заполняет анкету и сразу убирает из адресной строки, чтобы
пересланная ссылка не унесла с собой рассказ о здоровье.

Если ссылка почему-то не открылась, в приложении на вкладке «Анкета»
есть «Перенести ответы из бота вручную»: туда вставляется сообщение
бота «Что записано» целиком.

**Почему не вход по номеру телефона.** Номер — не пароль: его знают
родственники, соседи и любой, кому человек когда-то звонил. Вход по
одному лишь номеру открыл бы ответы о здоровье подопечного и его адрес
каждому, кто этот номер наберёт. Кроме того, для такого входа нужен
сервер, который хранит анкеты и отвечает из интернета, — сейчас
приложение лежит статическими файлами, и хранить там нечего.
Ссылка обоих недостатков лишена.

Адрес приложения бот берёт из настройки `SDUT_APP_URL`; по умолчанию —
рабочий адрес на Cloudflare. При переезде на другой хостинг достаточно
задать её, ничего не правя в коде.
