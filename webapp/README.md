# Навигатор помощи СДУТ — страница для мини-приложения MAX

Одностраничное веб-приложение: что делать при ухудшении состояния, как работает
горячая линия, модель долговременного ухода по приказу № 731 и ответы на
вопросы семей. Вкладок больше нет — всё собрано на одной странице девятью
блоками, внутри которых вопросы раскрываются по клику.

## Оформление

Палитра и приёмы сняты с оформления постов канала
[@SDUT63](https://t.me/SDUT63): тёплый кремовый фон, глубокий петроль, зелёный
СДУТ и песочный акцент. Из макетов канала на страницу перенесены фирменные
элементы:

- плашка-хештег в начале каждого блока (`.tag`), с реальными рубриками канала —
  `#КакЭтоУстроено`, `#ОценкаНуждаемости`, `#ПомощьПоСтандарту`,
  `#ПомощникРядом`, `#ТихийВечер`, `#ГородЗаботы`;
- короткая песочная черта под заголовком (`.rule`);
- кружки с линейными иконками и подписью капсом (`.row` + `.ic`);
- тёмная полоса-призыв внизу смыслового блока (`.band`);
- хештеги и слоган в подвале.

Шрифт — Golos Text, гарнитура российских госсервисов, весами 400–800.
Моноширинный шрифт убран: в макетах канала его нет, коды документов набраны
разрядкой (`.code`).

## Структура блоков

| Якорь | Блок | О чём |
|---|---|---|
| `#b-now` | Срочно | STOP-1 / STOP-2, красные флаги, что подготовить, ночь и выходные |
| `#b-line` | Горячая линия | ГЛ-001…ГЛ-005, координационный центр, контрольные звонки, чат-бот |
| `#b-model` | Модель СДУ | приказ № 731, как попасть, типизация, ИППСУ, 442-ФЗ |
| `#b-levels` | Оценка и уровни | действия из оценки, три уровня, ноль баллов, визиты организатора |
| `#b-care` | Практика ухода | замещать/ассистировать, бельё, кормление, перемещение, дневник |
| `#b-equip` | Оборудование | пункт проката ТСР |
| `#b-pall` | Паллиатив и семья | «Мы не привыкаем», 323-ФЗ ст. 36, выгорание, ЧК-СМП-001 |
| `#b-rights` | Права и контроль | отказы, Лист передачи, версии документов, KPI-Р / KPI-П |
| `#b-media` | Материалы | место под картинки и видео |

Ссылка вида `.../app#b-levels` открывает страницу сразу на нужном блоке.

## Настройка перед публикацией

Откройте `index.html`, найдите блок `CONFIG` в начале `<script>` и заполните:

```js
var CONFIG = {
  org:       "АНО «СДУТ»",
  phone:     "+78482000000",          // для tel:, только цифры и +
  phoneText: "+7 (8482) 00-00-00",    // как показать на экране
  hours:     "Пн–Пт, 08:00–20:00",
  botUrl:    "https://max.ru/...",    // ссылка на чат-бот с опросником
  tgUrl:     "https://t.me/SDUT63",
  email:     "info@example.ru",
  address:   "Тольятти, ул. ...",
  logoUrl:   "https://ваш-адрес/logo.png",  // пусто — текстовый знак «СДУТ»
  version:   "v1.2"
};
```

Пока `phone` и `botUrl` пустые, страница честно показывает «не заполнено»
вместо выдуманного номера и выводит подсказку о настройке. Подсказка исчезает
сама, как только оба поля заполнены.

**Кнопка вызова скорой `103` работает независимо от настроек.**

`logoUrl` подставляет настоящий логотип СДУТ в шапку. Если ссылка не откроется,
останется текстовый знак — подмена происходит только после успешной загрузки.

## Что проверить в содержании

Данные о модели СДУ собраны из вторичных источников и из макетов канала —
доступ к правовым базам из окружения был закрыт, построчной сверки с текстом
приказа не было. Перед публикацией стоит проверить:

- объём соцпакета по уровням: **11–14 / 18–21 / 25–28 часов в неделю**,
  основание — приказ № 731, п. 42–45 (цифры взяты с макета канала);
- порог **0–15 баллов**, при котором уровень нуждаемости не устанавливается;
- периодичность визитов организатора ухода: III — раз в месяц, II — раз в
  квартал, I — раз в полгода;
- сроки: первичная типизация и признание нуждающимся — 5 рабочих дней;
- перечень действий в блоке «Оценка и уровни»: на макете канала заголовок
  говорит про 18 действий, а в списке читается 17 — сверьте с оценочной шкалой
  и допишите недостающее.

Раздел «Источники» в конце страницы ведёт на КонсультантПлюс, ГАРАНТ и сайт
Минтруда.

## Картинки и видео

В блоке «Материалы» рядом с разметкой лежит
`<script type="text/plain" id="media-templates">` — инертный блок, он не
выполняется и не отображается на странице, из него просто копируют готовый
фрагмент.

**Картинка по ссылке:**

```html
<figure class="media">
  <img src="https://ваш-адрес/схема.jpg" alt="Что изображено" loading="lazy">
  <figcaption>Подпись под картинкой</figcaption>
</figure>
```

**Видео карточкой** — обложка с кнопкой, открывается в плеере RuTube, VK Видео
и подобных. В мини-приложении ссылка откроется штатным способом через мост MAX:

```html
<a class="media media--play" href="https://rutube.ru/video/ССЫЛКА/" target="_blank" rel="noopener">
  <img src="https://ваш-адрес/обложка.jpg" alt="" loading="lazy">
  <span class="media__badge" aria-hidden="true">&#9654;</span>
  <span class="media__label">Название ролика · 12 мин</span>
</a>
```

**Видео встроенным плеером** — нужен адрес именно для встраивания (embed):

```html
<div class="media media--embed">
  <iframe src="https://rutube.ru/play/embed/ID/" title="Название" allowfullscreen loading="lazy"></iframe>
</div>
```

Вставлять эти блоки можно в любой блок страницы — внутрь `<div class="q__body">`
у вопроса или прямо в `<div class="card">`. Посты канала удобно класть в
«Материалы» карточками с обложкой.

Две оговорки:

- Если картинка по ссылке перестанет открываться, блок сам покажет «Материал
  недоступен» вместо пустого места — за этим следит обработчик `error`.
- Встроенный плеер (`iframe`) зависит от того, разрешает ли видеохостинг
  встраивание. Если плеер не появляется — используйте вариант с карточкой.

## Запуск

Файл самодостаточен: никаких сборок и зависимостей, кроме Google Fonts. При
отсутствии сети шрифт корректно подменяется системным.

```bash
python3 -m http.server 8000 --directory webapp   # http://localhost:8000
python max_bot_integration.py                    # http://localhost:5000/app
```

## Подключение к MAX

Мини-приложение открывается по HTTPS-ссылке: разместите страницу на домене с
сертификатом (тот же сервер, что и вебхук бота) и укажите `https://ваш-домен/app`
в настройках мини-приложения MAX.

Страница написана как обычный веб-документ и не зависит от хост-моста. Если MAX
предоставляет JS-мост, скрипт использует его дополнительно — раскрывает окно,
подхватывает тему клиента, даёт тактильный отклик и открывает ссылки штатным
способом. Мост определяется по факту наличия и вызывается через `try/catch`.

> Имена методов моста (`ready`, `expand`, `openLink`, `HapticFeedback`) заданы по
> распространённой схеме мини-приложений. Сверьте их с документацией MAX: при
> несовпадении ничего не сломается, интеграция просто не активируется —
> исправьте объект `host` в конце `index.html`.

## Что учтено

- **Мобильный webview**: узкая колонка, крупные цели нажатия, панель действий
  под большим пальцем, отступы под вырезы экрана, липкая навигация по блокам с
  подсветкой текущего.
- **Обе темы**: светлая палитра объявлена в `:root`, тёмная только переопределяет
  токены — страница корректна и при системной теме, и при явном выборе клиента,
  плюс собственный переключатель в шапке.
- **Доступность**: нативные `<details>`, видимый фокус, контрастные цвета,
  `prefers-reduced-motion`, смысловые заголовки блоков.

## Правка содержания

Блоки — девять `<section class="block">` в `<main>`. Вопросы — элементы
`<details class="q">`; чтобы добавить вопрос, скопируйте соседний блок. Чтобы
добавить целый блок, скопируйте `<section>` целиком, задайте новый `id` и
допишите чип в `<nav class="chips">` — подсветка при прокрутке подхватится сама.
Цвета, шрифт и размеры собраны в переменных `:root` в начале файла.
