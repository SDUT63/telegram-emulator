# Навигатор помощи СДУТ — страница для мини-приложения MAX

Одностраничное веб-приложение для семей и коллег: что делать при ухудшении,
куда обратиться, как устроен долговременный уход, оценка нуждаемости, практика
ухода, оборудование, поддержка ухаживающих, паллиативная помощь и права.

Всё собрано на одной странице десятью разделами; вопросы внутри раскрываются
по клику, поэтому в свёрнутом виде страница читается коротко.

## Язык страницы

Страница написана для людей, а не для внутреннего оборота. Служебных
обозначений организации на ней нет:

| Во внутренних документах | На странице |
|---|---|
| `ГЛ-001…ГЛ-005` | пронумерованные шаги «что происходит после звонка» |
| `АЛГ-ВОЛ-001` | «оператор, прошедший специальное обучение» |
| `ЧК-СМП-001` | «отдельный порядок работы со скорой помощью» |
| `ТК-СДУ-ГИГ-01 v.2` | «у каждого документа есть номер версии и дата» |
| `СОП`, `ТК`, `ПАМ`, `РЕГ`, `ФОР`, `АЛГ`, `ЧК`, `НАВ` | описаны словами |
| `В / Мс / Ф / У / Р / С / Вол` | врач, медсестра, фельдшер, помощник по уходу, родственник, специалист сопровождения |
| `STOP-1` / `STOP-2` | «Опасно для жизни — звоните 103» / «Что-то не так — остановитесь и сообщите» |
| `KPI-Р` / `KPI-П` | «что изменилось у человека» / «как выполняли работу» |
| «типизация» | «оценка нуждаемости» |

Если будете дописывать разделы — держитесь этого же правила: код документа
ничего не говорит человеку, который звонит, потому что маме стало хуже.

## Оформление

Палитра и приёмы сняты с постов канала [@SDUT63](https://t.me/SDUT63) и группы
[vk.ru/sdut63](https://vk.ru/sdut63): тёплый кремовый фон, глубокий петроль,
зелёный СДУТ, песочный акцент.

Перенесённые с постеров элементы:

- плашка-хештег в начале раздела (`.tag`) с реальными рубриками канала;
- короткая черта под заголовком (`.rule`);
- **полоса плиток с кружками-иконками** (`.feats`) — тот самый ряд внизу
  постера, где под иконкой стоит короткая подпись;
- строки «кружок + подпись капсом + текст» (`.rows` / `.row`);
- полоса-призыв в конце раздела (`.band`) с иконкой слева и сердцем справа;
- хештеги и слоган в подвале.

### Цвет темы раздела

У каждого раздела свой цвет, как рубрики в канале. Он задаётся переменной
`--topic` и красит плашку, черту, кружки иконок, маркеры списка, номера шагов,
рамку раскрытого вопроса, стрелку и полосу-призыв. Чип в навигации
подсвечивается тем же цветом.

| Раздел | Рубрика | Цвет |
|---|---|---|
| Срочно | `#ЕслиСталоХуже` | красный |
| Куда обратиться | `#ГородЗаботы` | глубокий петроль |
| Что такое уход | `#КакЭтоУстроено` | зелёный СДУТ |
| Оценка и уровни | `#ОценкаНуждаемости` | шалфейный |
| Практика ухода | `#ПомощьПоСтандарту` | бирюзово-зелёный |
| Оборудование | `#ТехникаДляЖизни` | песочный |
| Тому, кто ухаживает | `#ШколаУхода` | приглушённый голубой |
| Паллиатив | `#ТихийВечер` | сине-серый |
| Права | `#ПомощникРядом` | тёмно-зелёный |
| Материалы | `#СДУТ` | серый |

Цвета объявлены токенами `--t-now`, `--t-line` и так далее в `:root`, а тёмная
тема переопределяет их светлыми вариантами. Чтобы добавить раздел, задайте ему
`--topic: var(--t-новый)` рядом с остальными правилами `#b-*`.

## Постеры канала

31 постер лежит в `webapp/img/` — сжаты до 900 px по ширине и переведены в
JPEG: 43,4 МБ исходников превратились в 3,4 МБ. Страница остаётся
самодостаточной и работает офлайн.

28 постеров расставлены по смыслу внутри ответов. Четыре — альтернативные
варианты тех же тем, они лежат в папке про запас и нигде не подключены:
`smena-belya-2`, `deystviya-ocenki-2`, `koordinacionnyy-centr-2`,
`stomy-katetery`.

Постер кликабельный: открывается в полный размер, чтобы можно было прочитать
мелкие подписи. В мини-приложении ссылка открывается штатным способом.

### Как добавить новый постер

Положите файл в `webapp/img/` и вставьте в нужное место:

```html
<a class="poster" href="img/имя-файла.jpg" target="_blank" rel="noopener">
  <img src="img/имя-файла.jpg" alt="Опишите, что изображено" loading="lazy" width="900" height="900">
  <figcaption>Подпись под картинкой</figcaption>
</a>
```

`alt` обязателен: по нему страницу читают экранные дикторы, и он же
показывается, если картинка не загрузилась.

Пересжать новые файлы можно тем же способом — 900 px по ширине, JPEG качества
82, прогрессивный.

### Картинки и видео по внешним ссылкам

Рядом с разделом «Материалы» лежит `<script type="text/plain"
id="media-templates">` — инертный блок, он не выполняется и не отображается.
В нём четыре готовых шаблона: постер из папки, картинка по внешней ссылке,
видео карточкой с обложкой и видео встроенным плеером 16:9.

Если картинка по ссылке перестанет открываться, блок сам покажет, что материал
недоступен, вместо пустого места.

Встроенный плеер (`iframe`) зависит от того, разрешает ли видеохостинг
встраивание. Если плеер не появляется — используйте вариант с карточкой.

## Настройка перед публикацией

Откройте `index.html`, найдите `CONFIG` в начале `<script>` и заполните:

```js
var CONFIG = {
  org:       "АНО «СДУТ»",
  phone:     "+78482000000",          // для tel:, только цифры и +
  phoneText: "+7 (8482) 00-00-00",    // как показать на экране
  hours:     "Пн–Пт, 08:00–20:00",
  botUrl:    "https://max.ru/...",    // ссылка на чат-бот с анкетой
  tgUrl:     "https://t.me/SDUT63",
  vkUrl:     "https://vk.ru/sdut63",
  email:     "info@example.ru",
  address:   "Тольятти, ул. ...",
  logoUrl:   "img/logo.png",          // пусто — текстовый знак «СДУТ»
  version:   "v1.2"
};
```

Пока `phone` и `botUrl` пустые, страница честно показывает «не заполнено» и
выводит подсказку о настройке. Подсказка исчезает, как только оба поля
заполнены. **Кнопка вызова скорой `103` работает независимо от настроек.**

`logoUrl` подставляет настоящий логотип в шапку — подмена происходит только
после успешной загрузки, иначе остаётся текстовый знак.

## Что проверить в содержании

Данные о системе собраны из ваших постеров и вторичных источников: доступ к
правовым базам, Телеграму и ВКонтакте из рабочего окружения закрыт, построчной
сверки с текстом приказа не было. Перед публикацией стоит проверить:

- объём помощи по уровням: **11–14 / 18–21 / 25–28 часов в неделю**
  (взято с постера «Три уровня», основание — приказ № 731, п. 42–45);
- порог **0–15 баллов**, при котором уровень не устанавливается;
- периодичность визитов организатора ухода: 3 уровень — раз в месяц,
  2 — раз в квартал, 1 — раз в полгода;
- сроки: первичная оценка и признание нуждающимся — 5 рабочих дней;
- перечень действий в разделе «Оценка и уровни»: на постере заголовок говорит
  про 18 действий, а в плитках читается 17 — сверьте со шкалой и допишите
  недостающее.

## Один файл для ноутбука

`Навигатор-помощи-СДУТ.html` — та же страница, собранная **в один файл**:
картинки и шрифт вшиты внутрь. Скачали, дважды щёлкнули — работает. Ни папки
с картинками, ни сервера, ни интернета не требуется.

Проверено с полностью отключённой сетью: 27 постеров отрисовываются, шрифт
Golos Text на месте, страница не делает ни одного внешнего запроса.

Размер — около 4,4 МБ. Файл **генерируется**, править его руками не нужно:
изменения вносятся в `index.html`, после чего он пересобирается командой

```bash
python build_offline.py
```

## Запуск обычной версии

`index.html` тоже открывается двойным щелчком — при условии, что папка `img/`
лежит рядом. Сборки нет, внешних зависимостей нет, кроме Google Fonts (при
отсутствии сети подставится системный шрифт).

```bash
python3 -m http.server 8000 --directory webapp   # http://localhost:8000
python webapp_server.py                          # http://localhost:5000/app
```

## Подключение к MAX

Мини-приложение открывается по HTTPS-ссылке: разместите страницу на домене с
сертификатом (тот же сервер, что и вебхук бота) и укажите
`https://ваш-домен/app` в настройках мини-приложения MAX.

Страница написана как обычный веб-документ и не зависит от хост-моста. Если MAX
предоставляет JS-мост, скрипт использует его дополнительно — раскрывает окно,
подхватывает тему клиента, даёт тактильный отклик и открывает ссылки штатным
способом. Мост определяется по факту наличия и вызывается через `try/catch`.

> Имена методов моста (`ready`, `expand`, `openLink`, `HapticFeedback`) заданы
> по распространённой схеме мини-приложений. Сверьте их с документацией MAX:
> при несовпадении ничего не сломается, интеграция просто не активируется —
> исправьте объект `host` в конце `index.html`.

## Что учтено

- **Мобильный webview**: узкая колонка, крупные цели нажатия, панель действий
  под большим пальцем, отступы под вырезы экрана, липкая навигация с
  подсветкой текущего раздела.
- **Обе темы**: светлая палитра объявлена в `:root`, тёмная только
  переопределяет токены — страница корректна и при системной теме, и при явном
  выборе клиента, плюс собственный переключатель в шапке.
- **Доступность**: нативные `<details>`, видимый фокус, контрастные цвета,
  `prefers-reduced-motion`, `alt` у всех изображений, смысловые заголовки.
- **Вес**: картинки грузятся лениво (`loading="lazy"`) и имеют заданные
  `width`/`height`, поэтому страница не прыгает при загрузке.

## Правка содержания

Разделы — десять `<section class="block">` в `<main>`. Вопросы — элементы
`<details class="q">`; чтобы добавить вопрос, скопируйте соседний блок. Чтобы
добавить раздел, скопируйте `<section>` целиком, задайте новый `id`, добавьте
правило `#b-новый { --topic: var(--t-новый); }` и допишите чип в
`<nav class="chips">` — подсветка при прокрутке подхватится сама.

Цвета, шрифт и размеры собраны в переменных `:root` в начале файла.
