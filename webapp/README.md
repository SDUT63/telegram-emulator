# Навигатор помощи СДУТ — страница для мини-приложения MAX

Одностраничное веб-приложение из шести вкладок: что делать при ухудшении
состояния, как работает горячая линия, что спрашивает опросник в чат-боте,
модель СДУ по приказу № 731, частые вопросы и устройство системы документов.

Материал вкладок «Что делать сейчас», «Горячая линия», «Опрос», «Вопросы» и
«Документы» взят из документа «Система документов по уходу СДУТ» v1.2 и
Мастер-реестра v1.2 — коды `ГЛ-001…ГЛ-005`, `АЛГ-ВОЛ-001`, `ЧК-СМП-001`,
уровни `STOP-1` / `STOP-2`, роли `В / Мс / Ф / У / Р / С / Вол`,
показатели `KPI-Р` / `KPI-П`.

Вкладка «Модель СДУ» опирается на приказ Минтруда России от 23.12.2025 № 731
«О реализации в Российской Федерации в 2026 году Типовой модели системы
долговременного ухода…» и Федеральный закон № 442-ФЗ. Проверьте её перед
публикацией: доступ к правовым базам был закрыт, поэтому фактура собрана из
вторичных источников, а не сверена построчно с текстом приказа.

Что стоит перепроверить в первую очередь:

- объём соцпакета по уровням — I до 14 ч/нед, II до 21 ч/нед, III до 28 ч/нед;
- сроки: первичная типизация и признание нуждающимся — 5 рабочих дней;
- перечень услуг соцпакета: он утверждается регионом и отличается по субъектам.

Раздел «Источники» в конце вкладки ведёт на КонсультантПлюс, ГАРАНТ и сайт
Минтруда.

## Настройка перед публикацией

Откройте `index.html`, найдите блок `CONFIG` в начале `<script>` и заполните:

```js
var CONFIG = {
  org:       "АНО «СДУТ»",
  phone:     "+78482000000",          // для tel:, только цифры и +
  phoneText: "+7 (8482) 00-00-00",    // как показать на экране
  hours:     "Пн–Пт, 08:00–20:00",
  botUrl:    "https://max.ru/...",    // ссылка на чат-бот с опросником
  email:     "info@example.ru",
  address:   "Тольятти, ул. ...",
  version:   "v1.2"
};
```

Пока `phone` и `botUrl` пустые, страница честно показывает «не заполнено»
вместо выдуманного номера и выводит подсказку о настройке. Подсказка исчезает
сама, как только оба поля заполнены.

**Кнопка вызова скорой `103` работает независимо от настроек** — экстренный
путь доступен даже до заполнения `CONFIG`.

## Запуск

Файл самодостаточен: никаких сборок и зависимостей, кроме шрифтов Google Fonts
(Golos Text и IBM Plex Mono). При отсутствии сети шрифты корректно подменяются
системными.

Локально:

```bash
python3 -m http.server 8000 --directory webapp
# http://localhost:8000
```

Вместе с ботом — страница отдаётся Flask-сервером по адресу `/app`:

```bash
python max_bot_integration.py
# http://localhost:5000/app
```

## Подключение к MAX

Мини-приложение открывается по HTTPS-ссылке, поэтому страницу нужно разместить
на домене с сертификатом (тот же сервер, что и вебхук бота, вполне подойдёт) и
указать адрес `https://ваш-домен/app` в настройках мини-приложения MAX.

Страница написана как обычный веб-документ и не зависит от хост-моста. Если MAX
предоставляет JS-мост, скрипт использует его дополнительно — раскрывает окно на
всю высоту, подхватывает тему клиента, даёт тактильный отклик и открывает
ссылки штатным способом. Мост определяется по факту наличия и вызывается через
`try/catch`, поэтому при его отсутствии или изменении API страница продолжает
работать без ошибок.

> Имена методов моста (`ready`, `expand`, `openLink`, `HapticFeedback`) заданы по
> распространённой в мессенджерах схеме мини-приложений. Сверьте их с актуальной
> документацией MAX: при несовпадении ничего не сломается, но интеграция просто
> не активируется — исправьте объект `host` в конце `index.html`.

## Что учтено

- **Мобильный webview**: узкая колонка, крупные цели нажатия, панель действий
  под большим пальцем, отступы под вырезы экрана (`safe-area-inset`).
- **Обе темы**: светлая палитра объявлена в `:root`, тёмная только переопределяет
  токены — страница корректна и при системной теме, и при явном выборе клиента,
  плюс собственный переключатель в шапке.
- **Доступность**: семантические вкладки с управлением стрелками, нативные
  `<details>` для вопросов, видимый фокус, контрастные цвета,
  `prefers-reduced-motion`.
- **Ссылки на разделы**: `#now`, `#line`, `#form`, `#sdu`, `#faq`, `#docs`
  открывают нужную вкладку сразу.

## Картинки и видео

Во вкладке «Модель СДУ» есть блок «Видео и материалы». Рядом с ним в файле лежит
`<script type="text/plain" id="media-templates">` — это инертный блок, он не
выполняется и не отображается на странице, из него просто копируют готовый
фрагмент.

**Картинка по ссылке:**

```html
<figure class="media">
  <img src="https://ваш-адрес/схема.jpg" alt="Что изображено" loading="lazy">
  <figcaption>Подпись под картинкой</figcaption>
</figure>
```

**Видео карточкой** — обложка с кнопкой, открывается в плеере RuTube, VK Видео
и подобных. В мини-приложении ссылка откроется штатным способом через мост MAX:

```html
<a class="media media--play" href="https://rutube.ru/video/ССЫЛКА/" target="_blank" rel="noopener">
  <img src="https://ваш-адрес/обложка.jpg" alt="" loading="lazy">
  <span class="media__badge" aria-hidden="true">&#9654;</span>
  <span class="media__label">Название ролика · 12 мин</span>
</a>
```

**Видео встроенным плеером** — нужен адрес именно для встраивания (embed), а не
обычная ссылка на страницу ролика. Соотношение сторон 16:9 держится само:

```html
<div class="media media--embed">
  <iframe src="https://rutube.ru/play/embed/ID/" title="Название" allowfullscreen loading="lazy"></iframe>
</div>
```

Вставлять эти блоки можно в любую вкладку — внутрь `<div class="q__body">`
у вопроса или прямо в `<div class="card">`.

Две оговорки:

- Если картинка по ссылке перестанет открываться, блок сам покажет «Материал
  недоступен» вместо пустого места — за этим следит обработчик `error` в скрипте.
- Встроенный плеер (`iframe`) зависит от того, разрешает ли видеохостинг
  встраивание и не запрещает ли его политика безопасности вашего домена. Если
  плеер не появляется — используйте вариант с карточкой, он работает всегда.

## Правка содержания

Разделы — это шесть `<section class="panel">` в `<main>`. Вопросы FAQ — элементы
`<details class="q">`; чтобы добавить вопрос, скопируйте соседний блок. Внутри
объёмной вкладки «Модель СДУ» вопросы сгруппированы блоками `<div class="group">`
с нумерованным заголовком. Цвета, шрифты и размеры собраны в переменных `:root`
в начале файла.
