# Навигатор помощи СДУТ — страница для мини-приложения MAX

Одностраничное веб-приложение: что делать при ухудшении состояния, как работает
горячая линия, что спрашивает опросник в чат-боте и ответы на частые вопросы.

Весь материал взят из документа «Система документов по уходу СДУТ» v1.2 и
Мастер-реестра v1.2 — коды `ГЛ-001…ГЛ-005`, `АЛГ-ВОЛ-001`, `ЧК-СМП-001`,
уровни `STOP-1` / `STOP-2`, роли `В / Мс / Ф / У / Р / С / Вол`,
показатели `KPI-Р` / `KPI-П`.

## Настройка перед публикацией

Откройте `index.html`, найдите блок `CONFIG` в начале `<script>` и заполните:

```js
var CONFIG = {
  org:       "АНО «СДУТ»",
  phone:     "+78482000000",          // для tel:, только цифры и +
  phoneText: "+7 (8482) 00-00-00",    // как показать на экране
  hours:     "Пн–Пт, 08:00–20:00",
  botUrl:    "https://max.ru/...",    // ссылка на чат-бот с опросником
  email:     "info@example.ru",
  address:   "Тольятти, ул. ...",
  version:   "v1.2"
};
```

Пока `phone` и `botUrl` пустые, страница честно показывает «не заполнено»
вместо выдуманного номера и выводит подсказку о настройке. Подсказка исчезает
сама, как только оба поля заполнены.

**Кнопка вызова скорой `103` работает независимо от настроек** — экстренный
путь доступен даже до заполнения `CONFIG`.

## Запуск

Файл самодостаточен: никаких сборок и зависимостей, кроме шрифтов Google Fonts
(Golos Text и IBM Plex Mono). При отсутствии сети шрифты корректно подменяются
системными.

Локально:

```bash
python3 -m http.server 8000 --directory webapp
# http://localhost:8000
```

Вместе с ботом — страница отдаётся Flask-сервером по адресу `/app`:

```bash
python max_bot_integration.py
# http://localhost:5000/app
```

## Подключение к MAX

Мини-приложение открывается по HTTPS-ссылке, поэтому страницу нужно разместить
на домене с сертификатом (тот же сервер, что и вебхук бота, вполне подойдёт) и
указать адрес `https://ваш-домен/app` в настройках мини-приложения MAX.

Страница написана как обычный веб-документ и не зависит от хост-моста. Если MAX
предоставляет JS-мост, скрипт использует его дополнительно — раскрывает окно на
всю высоту, подхватывает тему клиента, даёт тактильный отклик и открывает
ссылки штатным способом. Мост определяется по факту наличия и вызывается через
`try/catch`, поэтому при его отсутствии или изменении API страница продолжает
работать без ошибок.

> Имена методов моста (`ready`, `expand`, `openLink`, `HapticFeedback`) заданы по
> распространённой в мессенджерах схеме мини-приложений. Сверьте их с актуальной
> документацией MAX: при несовпадении ничего не сломается, но интеграция просто
> не активируется — исправьте объект `host` в конце `index.html`.

## Что учтено

- **Мобильный webview**: узкая колонка, крупные цели нажатия, панель действий
  под большим пальцем, отступы под вырезы экрана (`safe-area-inset`).
- **Обе темы**: светлая палитра объявлена в `:root`, тёмная только переопределяет
  токены — страница корректна и при системной теме, и при явном выборе клиента,
  плюс собственный переключатель в шапке.
- **Доступность**: семантические вкладки с управлением стрелками, нативные
  `<details>` для вопросов, видимый фокус, контрастные цвета,
  `prefers-reduced-motion`.
- **Ссылки на разделы**: `#now`, `#line`, `#form`, `#faq`, `#docs` открывают
  нужную вкладку сразу.

## Правка содержания

Разделы — это пять `<section class="panel">` в `<main>`. Вопросы FAQ — элементы
`<details class="q">`; чтобы добавить вопрос, скопируйте соседний блок. Цвета,
шрифты и размеры собраны в переменных `:root` в начале файла.
